## 修复挂机战斗 LuaException（FightPointMapOnHook:1423）

- 报错：`Modules/Fight/View/FightPointMapOnHook:1423 attempt to index local 'go' (a nil value)`，调用链 `DoMoveFight` ← `HeroAttack` 跳跃攻击的延时回位回调（:1132）。
- 根因：`RoleOnDead(pos)` 会把 `turnArray[pos].livego` 置 nil；而 `HeroAttack` 里 `this:turn()` 是立即调用的，下一次出手（甚至对方出手）会在 `ReturnTime` 之前就发生，跳跃攻击的回位回调执行时该单位可能已被打死，`dataAttack.livego` 读到 nil。
- 修改（同一文件）：
  1. `HeroAttack` 中在出手瞬间快照 `local livegoAttack = dataAttack.livego`，:1132 / :1146 / :1148 三处调用改用快照。
  2. `DoMoveFight` 入口加 `go == nil or IsNull(go) or tarpos == nil` 兜底直接 return（不调 func，避免单位已死还继续播技能/结算）；DOSetter 每帧重判、OnComplete 前也重判。
- 校验：`luac -p` 通过。

## 修复大招 cut-in 的「半透黑色方块」（effect 节点）

- 现象：`cn2-x1_badun_skill02_self.prefab` 里 `effect` 节点在游戏里是一块硬边半透黑矩形。
- 结构：`CameraAni(Animator) → … → MyCamera → effect`，effect 是内置 Quad，scale `(8.56,13.46,100)`、localPos `(0,3.27,18)`、layer 9、sortingOrder -15。
- 真正的开关：`Art/effectAni/hero/badun/CAM_badun_sk_02ANI.anim` 绑了 `[…/MyCamera/effect] MeshRenderer.material._Alpha`，`0 → 0.42 → 0.424 → 0`（0.50~3.05s）。预制里 `_Alpha=0`，所以编辑器看不出来，进游戏才露。
- 根因：`Art/effectMaterials/effec_M_0164.mat` 的 `_MainTex/_NoiseTex/_MaskTex` **全是 `{fileID: 0}`**。`MS/effect_alpha` 里 `RGB = MainTex.rgb × 噪声 × 顶点色`（`_Color` 纯黑 ⇒ 恒黑），`Alpha = 顶点色A × _Alpha × (MainTex.a × 噪声 × Mask)`；缺图时 Unity 回落纯白 ⇒ 整块 alpha 是常数 0.42，柔边本该由 `_MainTex.a` 做，没有就成硬边。
- 修法：只给 `_MainTex` 挂 `Art/EffectsOld/Textures/cn2-tex_glow_020.png`（128×128 径向柔边，`alphaIsTransparency=1`，21KB）。选 128 而非 512 是因为特效贴图随每个 prefab 包内嵌一份，14 个包各加一张 512 就是 4~5MB。
- 🔴 别用 Unity 保存这个 .mat：Unity 6 重新序列化会把 `_CullMode1` 从 0（双面）改成 1（剔除正面），quad 直接消失，还会带一堆 serializedVersion 噪声。**直接改 YAML 里 `_MainTex.m_Texture` 那一行**，diff 只有 1 行。
- 影响面：`effec_M_0164` 被 14 个 `X1Effect/Battle/*_self.prefab` 共用（巴顿/凯撒/拉斐尔/乔丹/嬴政/丹丁/真田幸村…），改材质等于全英雄一起修。
- 同类未修：`effec_M_0377`（longlv/waerjili）、`cys_mat_0187`（beimihu 的 `senceback`，`_Color.a=0.8`）也是空图纯黑，同样症状。
- 待办：`Prefabs/X1Effect/Battle` 那 14 个包要重打才会进真机（特效贴图不单独成包，靠 prefab 包带依赖）。
- 工具：`.workbuddy/tools/scan_soft_tex.py`（按 alpha 径向衰减挑柔边贴图）、`contact_sheet.py`、`make_fix_compare.py`；Unity 侧探针 `_probe_badun_*.cs` / `_verify_effec_0164.cs`。

## 选择国家面板 vs 新手引导：面板优先，引导排队（2026-10-20 12:45）

- 现象：首次进主界面，`CountryFlagSelectPopup` 延时 0.6s 才弹，强制引导（openType==4）
  监听的是 `MainPanel` 的 `UI.OnOpen` —— 该事件在 `OnShow` **之后**才派发，于是 GuidePanel
  先开、面板 0.6s 后压上去；GuidePanel 是全屏面板，还会把栈内面板一起关掉。
- 关键认知：`BasePanel:OpenUI` 的顺序是 `OnOpen → OnShow → DispatchEvent(UI.OnOpen)`。
  任何「挂在主界面 OnOpen 上」的逻辑都晚于 `MainPanel:OnShow` 的末尾。
- 改法：`CountryRankManager` 起 Timer 前**同步**置 `_firstEnterPopupShowing`；
  `IsFirstEnterPopupShowing()` 把「待弹（0.6s 空档）」也算占屏 —— 只判「已弹」等于没修；
  `GuideManager.ShowGuide` 遇占屏就把 `(id, args, argc)` 排进 `_PendingGuideList`，
  面板关闭时回调 `FlushPendingGuides()`（再延 0.15s，避开 `CloseStackPanel` 收尾）。
- 反向时序也做了：GuidePanel 已开着时面板等它关掉再弹。
- 兜底两条：`OpenPanel` 返回 nil 立刻解除占屏；待弹标记 2s 超时自动失效（防止引导被永久堵死）。
- 用例 `scripts/lua-tests/test_country_popup_vs_guide.lua`（19 项，含同屏违规检测），已入 tests.json 榜单组。
- 提交：1144f5ef2（源码+字节码）、8e6cb7fbf（用例+文档），均已 push。
- 提醒：`test_rank_head_flag.lua` 那 1 条失败是 `tests/lua-baseline.json` 里登记的已知基线，不是新坏。

## 运营面板 page_3 领奖红点不消失 / 可重复领（2026-10-20 12:5x，已提交 7a0584178 + ab1e8b78a）

- 现象：OperatingPanel 福利页 tab4（page_3，GrowthGiftPage 成长礼金）点「领取」后按钮红点不消失、
  按钮仍是「领取」，还能再点。
- 日志侧：`Logs/Editor.log` 里 node=203（RedPointType.GrowthGift）从 11:29 到 12:26 一直是 1，
  12:26:18 买完每日免费礼包才变 0（栈是 GrowthGiftPage:321）。整段日志**没有**一条
  `GrowthGiftPage:194`（领奖回调里 CheckRedPointStatus）——说明领奖回调压根没跑到那行。
  另外 12:26:18 那次 `RefreshRedObjectStatus type=203 state=0` 后面没有 `SetActive=false`、
  也没有 `No BindObjs`，即 BindObjs[203] 是**空表**（被 OnClose 的 ClearRedPoint 清过）。
- 真因①（数据/协议）：成长礼金 5 档 101~105 在 GlobalActivity 里对应 ActivityId 6/601/602/603/604
  （`CanBuyRechargeId` 列；OpenRules 是 3#6→3#601 链式解锁）。旧代码 `RefreshShowData` 用
  `IsActivityTypeOpen(GrowthReward)`（返回最后一个开启的，常是 604）去查列表里属于 6 的任务，
  `GetActivityInfo` 返回 nil ⇒ 旧源码在 `GrowthGiftPage:154` 抛
  `attempt to index local 'singleRewardData'`（已用 git stash 回滚源码复现）。
  服务器 `TakeActivityRewardHandler` → `AbstractActivity.takeReward` 会校验
  `sActivityRewardConfig.getActivityId() != id` ⇒ CFG_NULL，所以「奖励不发 + 状态不变 + 红点留着」。
- 真因②（红点生命周期）：`BindRedPoint()` 写在 `BindEvent`（只首次创建执行），而 `OnClose` 的
  `ClearRedPoint` 会 `BindObjs[rpType] = {}`；BasePanel 再次打开只走 `AddListener→OnShow`，
  ⇒ 面板第二次打开后所有页签红点永不刷新（与日志里空表吻合）。
- 改法：领奖链路统一用 `data.ActivityId`；回包后**先**把本条改成已领取（红点关/置灰/文案）再刷整表；
  加 `claimed`(闭包) + `claiming`(页面级，5 秒兜底) 双闸门；排序与「全部领完」判断对 nil 兜底；
  `BindRedPoint` 移到 `OnShow` 并加 `_redPointBound` 幂等，`ClearRedPoint` 里复位。
- 用例：`scripts/lua-tests/test_operating_growth_claim.lua`（23 项，驱动真源码，假 UI/假管理器），
  旧源码直接红。全量 lua 用例除 `test_rank_head_flag.lua`（已登记基线）外全绿。
- 坑位：`tests/tests.json` 会自动发现 `test_*.lua`，但分组标题要手动补；改完务必
  `scripts/lua-bytes-sync.sh <两个 lua>` 重编字节码，否则真机还是旧逻辑。
