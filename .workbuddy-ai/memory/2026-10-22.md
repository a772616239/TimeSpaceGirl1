## LoadingPanel 英文铭牌贴片「文字超框」修复

**现象**：`_output/art_translate_loading/*/preview_en.png` 里英文大字被贴片边界齐刷刷切掉
顶部/左边；标签、台词也贴到贴片边缘。实测 05 的 BRUTUS 顶部缺 46px、左边缺 16px，
03 缺 26px，07 缺 41px。

**根因**：`loading_plate_overlay.py` 的贴片 bbox 是用 `name_box` / 红条几何推算的，
但大字是斜排 15° + 纵向拉伸的，旋转后左上角会跑到 name_box 的
左外侧 `h/2·sinθ` 和上外侧 `w·sinθ + h/2·cosθ`，几何框根本框不住；
`NAME_HEADROOM` 只参与算 bbox、**没有约束字本身**，所以字照样往外长。

**改法**（脚本已重构）：
- `layer_ink_quad()`：图层 alpha 外接框 → 绕锚点旋转 + 平移到落点，得真实墨迹四边形；
- `build_lines()`：只排字，返回 [(图层, 锚点, 角度, **底图坐标**落点)]（顺序很重要：
  先定落点再定画布，反过来会自咬）；
- `plate_box()`：贴片 bbox = 红条 ∪ 台词带 ∪ 擦除区 ∪ 墨迹，再外扩 `PLATE_PAD=6`；
- 大字加硬约束：旋转后墨迹不得越过「名字区上沿 = name_box 顶 - 92」，越过就降字号；
- bbox 对 `LANGS` 全部语言取并集、小字擦除框按最长译名推 —— 保住
  「一张图一组 anchor」不变量（LoadingPlateGeom.lua 不按语言分表）；
- `geom.json` 新增 `ink_clip_px`，`verify` 新增硬检查「文字未越出画板」；面积上限 15%→25%。

**结果**：九张全部 9/9 PASS，`ink_clip_px` 全 0，贴片面积 8.2%~13.8%（原 10%~15%）。

## 环境坑（重要）

- 本机 shell 的 `grep` 实际是 **ripgrep 的 shim**，`grep "a\|b"` 不会按「或」匹配，
  会静默返回空 —— 排查代码时差点误判成「文件被回滚」。**判内容一律用 python 直读**。
- 仓库 `.git/hooks/post-commit` 是 Qoder 的 tracker。这次 `git commit` 之后，
  改动被并进了另一个 agent 的提交（message 是 `docs(memory): 测试服部署全链路…`），
  内容没丢但 **commit message 与改动不符**。提交后要 `git show --stat HEAD` 核对。

## 机器人节奏重构：一个「醒来」总闸（用户要求 20~240 分钟）

**用户诉求**：回复频率别太高，随机 20~240 分钟回一次，装成躺平挂机的主；
英雄公告也要挂在「醒来」上，而不是独立定时器。

**根因**：旧实现是三个互不相干的定时器（喊话 3~12 分钟、公告 25~75 分钟、回复秒级），
机器人比真人还勤快，一眼假。

**改法**（服务端 `BotManager`）：
- 删 `maybeChatter/maybeAnnounce` 与 `nextChatterAt/nextAnnounceAt`；
- 新增 `nextActiveAt: Map<uid, epochMs>`，每个机器人独立随机 20~240 分钟醒一次；
- `tick()` 顺序：`maybeFlipOnline → maybeWake → maybeReply → publishStatus`；
- `onActive()` 醒来**只做一件**：回话 > 公告(40%) > 闲聊(40%) > 纯挂机(20%)；
- `onWorldChat` **只记账不排回复**（`lastHumanMsgId/Text/At`），`schedulePendingReply()`
  在醒来那一刻才判断 `lastHumanMsgId > lastBotMsgId`；
- 新增 `replyMinGapSec=1200`（两次 AI 回复硬间隔）、`replyFreshSec 600→14400`
  （必须 ≥ `activeMaxSec`，否则醒来时消息全过期，表现为「永远不回」）。

**关键判据**：`replyFreshSec < activeMaxSec` ⇒ 机器人永远回不了话，是个隐蔽的死锁。

**顺手修**：DSH 会吐重复句（`yeah lol just idlin rnyeah lol just`），
`BotText.collapseRepeat()` 用「尾部是否等于自身前缀」找最小重复切点，8 个 case 单测通过；
`haha haha`、`gg wp gg wp`（重复片段 <6 字符）不误砍。

**控制台**：`console.html` 每个机器人卡片加「下次醒来 2h42m」倒计时 + 进度条，
面板标题显示「节奏 20~240m 醒一次」；进度基准用「首次看到的剩余时间」，
剩余时间跳大即视为新一轮、重置进度条。

**环境坑**：本机无头 Chrome 被沙箱拦（`sandbox initialization failed`），
截不了控制台图；验证只能走 `/api/snapshot` + 用 node 跑离线渲染单测。
另外 `curl 127.0.0.1` 会命中代理返回 502，要加 `--noproxy '*'`。

## 点 Tester 弹出 Nova 的面板 = 客户端残留，不是数据串号

**现象**：世界频道点假玩家 Tester 的气泡，弹出的是 Nova 的个人面板。

**根因链**：Tester 是控制台「模拟玩家发言」注入的假玩家，uid 固定 `fakeSenderUid=99990001`；
`user` 集合里没有这个号 → `PlayerLogic.getOneTeamInfo → UserManager.getUser` 抛
`1-UserManager::getUser null exception：99990001` → `BaseHandler` 打日志后**不回包** →
客户端 `PlayerInfoPopup` 只在**收到回包的回调里**刷新 → 面板停在**上一次**打开的玩家（Nova）上。

**诊断口径**：搜日志 `protoID=16650`，行里 `playerId: 99990001` 就是它。

**两道修法**：
1. `handler/player/GetPlayerOneTeamInfo` 包 try-catch，查不到就回一个**合法但空**的面板
   （uid + name=uid 字符串 + level 1 + head 71000/frame 80000 + `team.totalForce=0`）。
   字段必须齐 —— 客户端 `FormationAdapter` 第一行读 `teamInfo.totalForce`，team 为 nil 直接报错。
2. `clone_bot_user.js` SPECS 加第三条：Kai(90000002) → `99990001/Tester`，让假玩家有完整面板。

**顺带踩到的坑（更隐蔽）**：本地 `mongo` 4.0 shell 的 `NumberLong` **没有 `_bsontype`**，
`isBson()` 判定失败 → 被 `for...in` 拆成 `{floatApprox,top,bottom,exactValueString,tojson}`，
服务端报 `No mapping metadata found for long`，`bot team` 直接失败。
判定：`$type` 看 `playerManager.createTime` 是 `object` 还是 `long`；
连带症状是**文档体积翻倍**（正常 1.4MB → 坏 3.3MB）。
修法：`isBson()` 补 `floatApprox/exactValueString` 判断 + `repairShellNumbers()` 还原。

**部署**：本地 `patch_local.sh`（FILES 加了 handler，21 个 class）；测试服 jar v10
`66d85181c25a60655e88aa3e1b82ecdf`（以 v9 为基准打，2005 class），两边都建了 Tester 文档，
`bot team 99990001` → `name=Tester level=40 force=14678 heroes=5 country=pt`。
