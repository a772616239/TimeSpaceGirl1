# 2026-10-23

## 发线上包不同步服务端表 —— 补 ③-1 环节（00:11–00:30）

**现象**：用户报「刚刚 Jenkins 发线上包，没有 clone 表」。实指 `TS-Android-Release #21`
（2026-10-22 20:39，clone 在 `a93b955d9`，现网环境，release 口径）—— 包里的客户端表是新的，
线上服 `conf/server` 的 txt 还是旧的。

**三层根因（缺一层都推不出表，排查时按这个顺序看）**：
1. **发线上包这条路上根本没有同步动作**：Release 的资源准备走 `EXPORT_TABLES=false`
   → `resource_build.sh --action ab`；而 `table_sync` 只挂在 `--action export` 之后
   ⇒ 导表不跑、同步也不跑。这是结构性缺口，不是参数忘了勾。
2. **clone 落后时连代码都没有**：`#21` 的 clone 停在 `a93b955d9`，早于 22:00 那批
   table_sync 提交，`scripts/table_sync.py` 文件都不存在。
3. **clone 没有基线 = 永远「首次运行」**：`build/table_sync/state.json` 是 gitignore 的，
   首次运行只建基线、一张不推。即使前两层都修好，job 跑完表还是不动 —— 静默失败。

**改法**（提交 `642087f6e`，已 push）：
- `TS-Android-Release` 新增 `③-1 服务端表同步（包服一致）`，插在 ③-0 资源准备之后、
  ③ 打包预检之前；不依赖 `EXPORT_TABLES`。新参数 `SYNC_TABLES=apply|check|off`（默认 apply）、
  `SYNC_RESTART`（默认 false：线上重启会踢线，必须显式开）。
- `table_sync.py --env <SERVER_ENV>`：目标从 `scripts/build_envs.json` 的 `tableTargets` 取
  （现网→`gs`、测试服→`local`、正式服→`[]` 直接跳过 rc=0）。**映射只放 build_envs.json 一处**，
  别在 job/脚本里再写一遍 case 分支。
- `ci_sync.sh` 第④步：`rsync -a --update` 开发目录的 `build/table_sync/state.json` 到 clone。
  `--update` 是关键 —— 只前移不回退，CI 自己推过的那次比开发目录旧账本更可信。
- 文档：`docs/table_sync_skill.md` §2.1 重写成「两条入口 + 四条结论」；`docs/jenkins_ci.md`
  参数表补两个参数。

**现状体检（只读，`--env 现网-129.226.213.65`）**：基线已存在 → 候选 6 张、**可推 0 张**，
全部被结构体检拦下（Language `COL_LOSS`、EncouragePlan/EncourageTask/MultiLanguage `ROW_LOSS`、
ChannelRechargeIdConfig `HEADER_DIFF`、RewardItemConfig `REVIEW`）。
⇒ 线上服与导出产物除这 6 张外已一致，新环节上线不会突然大批推表。

**验证口径**：`.jenkins/lint.sh` 21 个 job 全过（含 pipeline-model-converter 语法校验）；
`apply-jobs.sh --only TS-Android-Release` 已下发，Jenkins 参数表确认出现
`SYNC_TABLES=apply` / `SYNC_RESTART=False`。

**环境坑**：
- 沙箱拦 `git stash`（规则：禁止删 `.git`）⇒ **没法在本地跑 `ci_sync.sh` 验证**，
  打包 clone 的同步只能等下一次 Jenkins 构建的 ①-1 步，或人工在 clone 里
  `git fetch && git reset --hard origin/release`。
- `curl` 访问 Jenkins API 时 `?tree=...[a,b]` 的方括号会被当 glob（报 `bad range in URL`），
  必须加 `-g`；另外本机要 `--noproxy '*'`。
- 提交时 shell heredoc 的输出会串：commit 已成功落库，屏幕上却打出
  「no changes added to commit」——**以 `git show --stat` 为准**，别按那句报错重提交。
