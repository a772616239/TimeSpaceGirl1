## 聊天记录持久化（Redis 兜底 + 最少留 3 条）（2026-10-10 19:20，已改代码+编译+dry-run，**未部署**）

### 根因确认（源码证据）
- `serverlogic/.../chat/messge/MessageCache.java` 的 `worldMsg/sysMsg/crosssysMsg` 三个 `LoopQueue` 是 **static 内存对象**，全工程没有任何"启动时从 Redis/Mongo 恢复聊天"的代码 → 进程重启即清空。
- `LoopQueue`：容量 200、单次最多取 30（`initLength=30`/`getMaxLen`）、有效期 7 天（`diffTime`），发满环形覆盖。
- 客户端（Lua，非 C#）拉取入口 `Assets/ManagedResources/~Lua/Modules/Net/NetManager.lua:3599 RequestChatMsg(type,msgId)`；`Modules/Chat/ChatManager.lua`：`_CHANNEL={SYSTEM=0,GLOBAL=1,CrossRealm=16}`，每 2s 轮询、约 `InitData` 用 msgId=0 拉一次。
- **纠正之前的一个判断**：世界/跨服聊天**其实有 Redis 存档** —— `ChatLogic.onSendChatSuccess()` 每条消息都会写 `serverId:CHAT_INFO_CACHE:<chatType>`（list，>1000 条才 lPop，**无 TTL**）；只是没有任何代码用它来恢复内存队列。系统消息（chatType 0）不走这个方法，所以系统消息确实零存档。

### 🔴 macOS /home 是 autofs 挂载点（v1 脚本失败真因）

## 🔴 事故与修复：玩家「登录不进去」（2026-10-10 23:05–23:10）

### 现象
客户端能登录、能进选服界面、能选中「霓虹都市」、`tk/userLogin` + `tk/getUserInfo` 都成功（登录服发了 `uid=10000226 / token 2010260353`），但连游戏服之后就没有下文。

### 排查路径（按证据链）
1. **本地游戏服日志 23:06–23:07 只有例行 MinuteTask，`online use num::0`** → 连接根本没到达本地服。
2. 本地库 `m5_x1_game_10002.user` 条数 = 0；生产库 `m5_x1_game_10001` 最大 `_id:10000225`、**无 10000226** → 用户在任何地方都没被创建 ⇒ 客户端连的是 16181（对的），只是连不上。
3. 客户端侧确认：`LoginPanel.lua:256-257` `SocketAddress = list.ip` / `SocketPort = tonumber(list.port) or 0` ⇒ 目标 129.226.213.65:**16181**，客户端无 bug。
4. **frps 日志**：`23:05:40.901 proxy closing` + `listener is closed: accept tcp [::]:16181` + `client exit success` ⇒ **16181 公网入口已关闭**。
5. **frpc 日志**（真凶）：
   ```
   23:05:40.476 connect to server error: dial tcp 127.0.0.1:50470: connect: connection refused
   ```
   frpc 本该连 `129.226.213.65:7700`，却跑去连 `127.0.0.1:50470`，然后每 20s 无限重试到天亮。

### 根因
**frpc 继承了 agent 沙箱的代理环境变量。** 本机 shell 里有 `HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:5xxxx`（沙箱的本地透明代理，**端口会随会话轮换**，实测 23:05 时从 `:50470` 变成 `:56236`），且 MCP 配置里 `transparent_proxy: true`。frpc（Go）会读这些变量当代理地址；代理一换端口，frpc 就永远连不上 → **隧道静默中断：进程还活着、日志在刷、但服务已死**。这是最坑的一类故障。

### 修复
1. `frp/run-frpc.sh` 启动时用 `env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy -u ALL_PROXY -u all_proxy ...` **剥掉代理变量** → 实测 1 秒连上、`start proxy success`。
2. 新增 `recover.sh`：幂等一键恢复（Redis 6479 → 游戏服 16081 → frpc），且能识别「进程活着但 proxy 未注册」这种假活状态并重启。
3. 新增三个 LaunchAgent（`~/Library/LaunchAgents/com.tsg.shard10002.{redis,shard,frpc}.plist`，均 RunAtLoad + KeepAlive，环境变量里显式置空代理）+ `install-launchd.sh {install|uninstall|status}`（带失败自动回滚）。
   🔴 **`launchctl` 在 agent 沙箱里被拦**（`Bootstrap failed: 5: Input/output error`）⇒ **必须用户自己在终端执行**。

### 复盘要点
- 「进程在跑」≠「服务可用」。隧道类组件必须验证**注册状态**（`start proxy success`），不能只看 pgrep。
- agent 沙箱环境变量会污染被拉起的常驻进程。凡是长驻的外部进程（frpc/frps/其他 daemon），启动时必须 `env -u` 剥代理，或交给 launchd。
- 客户端 `languageDicStr no find Str: 霓虹都市 / 霓虹序曲` 是**红色警告但非故障**：区服名不在客户端 i18n 表里，`GetLanguageStrByStr` 回落显示原文，不影响功能。

## 23:37–23:50 登录仍被踢：`errCode 30014` 真因 = 镜像延迟，v2 推送式重做

用户客户端日志：`getUserInfo` 正常返回 `{uid:10000226, token:919336709}`，随后被踢
`[Network ERROR DEBUG] errCode = 30014 errMsg = 鎮ㄧ殑璐﹀彿token涓嶆纭?..`（GBK 误读 UTF-8）＝**「您的账号token不正确」**。

### 定位（日志直接给出证据）
```
23:36:44.315 AuthManager#30 ----登录校验01---- uid=10000226,token=919336709,tokenKey=JL_TOKEN:10000226,tokenK=960068271
23:36:44.315 AuthManager#43 ----登录校验5---- token=919336709,serverToken=960068271
```
生产 Redis 已是 `919336709`，本地此刻还是 **23:27 那次的旧值 `960068271`** ⇒ 是**镜像延迟**，不是鉴权逻辑。

### v1 的两个致命缺陷（实测，都得写进记忆）
1. **延迟 ~3–4s**：每轮全量 225 key 各 fork 一个 `redis-cli`，本地读取管道被 225 次进程启动塞满，增量排到队尾。（记忆里"0.27s"是单 key 受控测量的乐观值，不代表登录路径。）
2. **反噬生产**：`INFO commandstats` 6s 差分 = `get=5400 / eval=24` ⇒ **908 ops/s**，而生产 Redis 全部流量也是 908 ops/s —— 镜像一个人把生产打满。停掉镜像后同法测为 0.1 ops/s，归属确认无误。
   （中途被 `instantaneous_ops_per_sec` 的 1409/1690 误导过一次，该指标 1s 采样噪声大；**6s 以上的 commandstats 差分才可信**。）

### 网络物理量（决定方案边界）
| 测量 | 值 | 说明 |
|---|---|---|
| `ping 129.226.213.65` | 0.08–0.14 ms | **假的**（被拦截），不可用 |
| `curl` 登录服 TTFB | ~0.35 s | 可信，含 TCP 握手 + 处理 |
| `ssh gs echo hi` 热往返 | ~490–510 ms | 所有"远程推送"方案的延迟下限来源 |
| 经 `-L` 隧道 `redis-cli PING` | ~490 ms | ＝2 个 WAN 往返，推出单程约 245 ms |

**结构性结论**：token 由登录服在 `getUserInfo` 里生成，与客户端连游戏服只差约 0.2–0.4s，任何远程同步都要过一次 WAN 单程 ⇒ **"预投递"不可能被做成保证**；能赢是因为**客户端登录包要跨 WAN 两次**（客户端→云服:16181→frp 反向隧道→本地:16081），镜像只跨一次，结构性余量约 0.3–0.5s。

### 方案取舍
| 方案 | 结论 |
|---|---|
| `MONITOR` | 零生产配置改动；但开销按**总命令数**算，且自家 `GET` 会被正则命中形成**自激回环**（须靠"只匹配写命令"规避）。弃用。 |
| **keyspace 通知（采用）** | 开销按**写命令数**算 —— 实测生产写命令 **0 ops/s**，几乎免费。 |
| 本地 `REPLICAOF` 生产 | 需隧道 + fork 全量 42MB；resync 会 `FLUSHALL` 本地 key；且把生产 `JL_USER_SERVER_INFO`（属 10001）一起灌进来，破坏隔离。弃用。 |
| 本服 Redis 指向云上 | 每个 Redis 操作过 WAN（RTT ~500ms），游戏服不可用。弃用。 |

### 踩坑：`notify-keyspace-events` 少了 `$`
Redis 通知分类：`K`=keyspace 通道 / `$`=**string 类（`SET`）** / `g`=generic 类（`DEL`/`EXPIRE`）。
**只设 `Kg` 收不到 `SET`**（实测只收到 `del`），必须 **`K$g`**。运行时配置、不改 redis.conf、不重启，但 **Redis 重启会回落** ⇒ 脚本每次建链 + 每 120s 幂等重设。

### v2 实现（`token-sync.sh` 重写，interface 不变）
- 快通道 = `PSUBSCRIBE '__keyspace@0__:JL_TOKEN:*'` 常驻连接 → 收写事件 → `GET` → `key\tvalue` 回传。
- 首帧全量 dump（覆盖断线期间变更）+ 每 120s 全量兜底。
- 本地落地改成**单条常驻 `redis-cli` 喂 stdin**，杜绝 per-key fork；`v` 为空则发 `DEL`（生产删了的 token 本地跟着删）。
- 🔴 **远端后台兜底子壳必须显式 `kill`**：它持有 stdout，不收就等不到 EOF，ssh 不关通道，本地 `read` 永久挂住。
- 新增 `selftest` 子命令（写假 key 到生产 → 测本地可见毫秒 → 两端清理）。

### 验收
```
✓ 生产写入→本地可见: 291 ms      （v1 约 4000 ms）
✓ 生产 Redis 负载:  0.1 ops/s    （v1 908 ops/s）
✓ 225 条 JL_TOKEN 逐字节完全一致（含 uid=10000226）
✓ launchd 托管下 KeepAlive 自动拉起新脚本（kill 后 ~10s 由 ThrottleInterval 重启）
```
