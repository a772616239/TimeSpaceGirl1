# 2026-10-10 工作日志

## 修复 TimeSpaceGirl1(Unity 项目) 的 git 仓库损坏

**现象**：git 客户端里仓库"无法显示"——HEAD 看起来只剩 1 个文件，整项目像被清空。

**根因链（三层叠加）**
1. `.git/objects/pack/` 下 4 个 pack 的 `.pack` 数据文件全部丢失（只剩 `.idx`/`.rev` 残留，约 3GB 对象没了）。
2. `.git/objects/info/commit-graph`（5 月的旧文件）+ 残留 `.idx` 让 git 误以为对象还在：
   - commit-graph 引用丢失对象 → `git fetch` 直接拒绝执行；
   - 孤立 `.idx` 让协商误报"已有对象" → fetch 报 `unresolved deltas left after unpacking`。
3. 坏引用（R2~R8/main/releaseR1/origin/*）指向丢失对象 → fetch 协商阶段报 `bad object`。
4. 最后一个本地提交 `6626054 "fix: 修复日语用户首次启动显示中文的问题"` **把 46527 个文件全删了**（树里只剩 1 个文件），索引也只剩 1 条 → 这才是 GUI"显示为空"的直接原因。
5. 磁盘上还真的少了 9519 个受跟踪文件（目录在、文件缺）。

**修复动作**
1. `git config gc.auto 0` / `gc.autoDetach false` / `gc.pruneExpire never`（防再次 gc 清包）。
2. 备份 `.git/refs` + `packed-refs` → `.git/refs-backup-20261010-165513/`。
3. 移走过期 `commit-graph`（→ `.bak-20261010`）、孤立 pack 的 `.idx`/`.rev`、坏引用 `packed-refs` 与 `refs/remotes/origin`（全部改名到备份目录，未删除）。
4. 因原地 fetch 解包失败，改用 `git clone --mirror` 到 `/tmp/tspg1-recovery.git` 拿干净对象库（74220 对象 / 3.3GB 单包），拷回 `.git/objects/pack/`。
5. 重建全部本地/远程分支引用（本地 `release` 保留，未覆盖）。
6. `git reset --mixed df8f7e0`：release 指回健康提交，重建索引（46527 条）。
7. `git checkout --pathspec-from-file=/tmp/deleted.z --pathspec-file-nul` 恢复 9519 个磁盘缺失文件。
8. `git reflog expire --expire=now refs/stash` 清掉 72 条失效 reflog。

**结果**：`git fsck --full` 零错误（仅正常 dangling）；13 个分支全部可读；工作区 46527 个受跟踪文件齐全；`release` 领先 `origin/release` 1 个提交（`df8f7e0`）。
