- **根因**：LuaJIT `lj_arch.h:647` 默认 `#define LJ_PAGESIZE 4096`；其 mcode 按该值对齐后调 `mprotect`，在 16KB 页设备上内核要求 16384 对齐 ⇒ JIT 代码页失效/崩溃。**光换 NDK 修不好，必须连 LuaJIT 一起换**。
- **采用方案**：`alex4814/tolua_runtime`（维护至 2025-01）—— 其 `luajit-2.1` submodule = **LuaJIT 2.1.ROLLING**（2025-01-13），CMake 构建，支持 `ANDROID_NDK_HOME=... ./build_tolua_android_arm64.sh`；另在 `cmake/luajit2.cmake` 注入 `-DLJ_PAGESIZE=16384`（仅 ANDROID 生效）；`LJ_GC64` 默认 ON，与原 arm64 库一致。
- **环境**：cmake ✅、git ✅、ninja（pip 装入 managed venv）✅、NDK = **下载 r28 zip（950MB）**；本机 Unity 自带仅 r23b、Android Studio 仅 r19，均不满足 r28。

## 结论存档：升 Unity 到 2023.2.22f1 **不能**解决 16K 问题（2026-10-12 追问）
- 用户问「2023.2.22f1 能解决上述所有的 16k 问题吗」→ **不能**，三条硬理由：
  1. **引擎只管 Unity 自出的 4 个库**（libunity/libil2cpp/libmain/lib_burst_generated），本工程这些**已全绿**（实测 13 个 .so / 0 不合规，libunity·libil2cpp·libmain 全 `p_align=16384`，libmain 已 r23b）⇒ 升引擎在这条线**收益为零**。
  2. Play 点名的库全是**第三方/自编**，与编辑器版本无关：Firebase ×3（r21e，官方预编译，实测 12.8.0/12.10.1/13.16.0 全 r21e，只能等上游）、libnative-googlesignin（r17，已 commit `72502790b` 清理）、libtolua（GCC 无 `.note.android.ident`，根因是 LuaJIT `LJ_PAGESIZE=4096`）。换引擎不会改动这 3 类字节。
  3. **2023.2.22f1 不在 Unity 官方 16KB 支持清单内**。官方清单 = `2021.3.48f1+ / 2022.3.56f1+ / 6000.0.38f1+ / 6000.1+`；2023.2 是已 EOL 的 Tech Stream，2023.2.22f1 只是 2025-09 的 CVE 安全补丁版。本工程现役 **2022.3.62f2c1 ≥ 2022.3.56f1，本身就在支持线内**（这正是 libmain 为 r23b、门槛1 全绿的原因）。
- ⚠️ 中文博客/Unity 中国社区 AI 回答里流传的「16KB 从 Unity 2023.2 LTS 起原生支持」是**错的**（MuseChat 生成），别据此升引擎。
- 现役 13 个 .so 的 NDK 实测：`libunity/libil2cpp/libmain = r23b`、`libcrashlytics ×4 = r25b`、`libdatastore_shared_counter = r25c`、`libFirebaseCpp{App-12_10_1,Analytics,Crashlytics} = r21e`、`libnative-googlesignin = r17`、`libtolua = ?(GCC)`。取证工具在跨仓 `main_android/Release/tools/`（`verify_16k.py` / `so_meta.py`）。
