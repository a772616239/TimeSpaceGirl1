## 八日礼包（EightDayGift, Type=56）改签到制

需求：天数必须玩家自己点签到才记，离线不自动涨；允许断签，回来续算一天（累计制，不重置不补签）。

- 关键结论：**不用改服务端**。反编译 `gameSrv-1.0.0.jar` 的
  `NewEightActivity.takeRewardsProcess` 只校验 `getSoFarWentDays(createTime, now) >= 配置Values-1`
  （即建号已过 N-1 个自然日），比签到口径宽松 ⇒ 客户端收紧不会被拒，本地判重被清也有服务端兜底。
- 实现：`Common/functions.lua` 末尾新增 `EightDaySign*` 纯函数（自然日序号存 PlayerPrefs，键带 uid；
  存**序号**不存时间戳，避开 PlayerPrefs.GetInt 的 2038 溢出）；`nextDay` = 第一个未领的天 = 今天可签的那天。
- 口径统一三处（记忆红线：入口红点必须与面板同口径）：`EightDayGiftPanel`、
  `ActivityGiftManager.CheckEightRedPoint`、`ActivityGiftManager.CheckRedFunc(CourtesyDress_SevenDay)`；
  福利面板 `CourtesyDressPanel` 5 处 `canRewardDay`（原= 服务端 progress = 自然日，比独立面板宽松）
  改调新增的 `ActivityGiftManager.GetEightCanRewardDay()`。
- 签到日期只在领奖成功回调里落盘，请求失败不算签到（不丢奖励）。
- 顺带修：`Refresh()` 先 Stop 旧倒计时 timer（原 timer 跨天后会继续覆写 day.text）。
- 测试：`scripts/lua-tests/test_eight_day_sign.lua` 28 条全绿；`test_courtesydress_cardslide.lua` 补 stub。
- commit `f75db10a8` + `33a9202fa`（已 push release）。
