# Capybara Merge: Tower Defense —— 重新命名建议

> 前提：把线上现名 `Capybara Merge: Tower Defense` / 「卡皮巴拉防线：水豚合成塔防」当作**没有**，从零取名。
> 数据来源：2026-10-24 网络检索（Play 页面 / 第三方榜单），非 Play API 全量扫描；碰撞只代表「公开可见范围内未被占用」。

## 一、结论

| 位置 | 推荐名 | 字数 | 一句话理由 |
|---|---|---|---|
| zh-CN | **水豚当关：卡皮巴拉合成塔防** | 13/30 | 「一夫当关」的化用 ⇒ 四个字说出「只有一条道，谁也不许过」 |
| en-US | **No Passing: Capybara Merge TD** | 29/30 | 「No Passing」是现实里的交通标志，同一句话把单车道机制讲完，且不与任何同类撞名 |

共同内核：**它们过不去**。品牌位放「机制梗」，品类词只留 Capybara / Merge / TD（水豚 / 合成 / 塔防），不再堆第四、第五个词。

## 二、为什么现名必须换（不是好不好听的问题）

同类产品至少 10 款，命名公式全部是 `Capybara + 动词/名词`：

| 游戏 | 命名位 | 量级 | 玩法标签 |
|---|---|---|---|
| Capybara Go! | Go | 10M+ | 放置跑酷 |
| Battle, Capybara! | Battle | 410K | 背包合成 + 塔防 + 僵尸 |
| Capybara Gear Up! | Gear Up | 1K+ | 背包合成 + 进化 + 僵尸防守 |
| Capybara Grid Hero | Grid Hero | — | 网格合成 + 塔防 + roguelike |
| Capybara Survivor: GOGOGO! | Survivor | — | 幸存者 + 随车塔防 |
| Capybara Party: Hide & Defend | Party | — | 躲藏 + 塔防 |
| Winter Wipeout: Capy Squad | Wipeout | 1K+ | 方块弹道 + 水豚射击 |
| 卡皮巴拉快跑 / 塞车 / 砰 | 快跑 / 塞车 / 砰 | — | 跑酷 / 停车 / 塔防射击 |

**`Capybara Merge: Tower Defense` 在这个列表里排第 11，而且它是唯一一个「没有任何品牌位、四个词全是品类词」的名字。**
后果有三条，都不是审美问题：

1. **搜索页里认不出来**：用户搜 capybara 看到 10 个都是 `Capybara X`，你的标题没有任何一个词是别人没有的。
2. **广告素材没有钩子**：买量素材最后 3 秒放标题是为了被记住；`Merge: Tower Defense` 记不住，用户下次还是靠关键词找，等于每次都要重新买。
3. **元数据政策风险**：Play 的元数据政策明确禁止「标题堆砌关键词 / 与功能无关的重复词」。四个词全砸在品类上，是这条政策最容易被判定的形状（不必然拒审，但被拒时改标题=重新走一轮审核）。

## 四、落成变体 C 的具体字段

```
zh-CN  title: 水豚当关：卡皮巴拉合成塔防      （13，保留 水豚/卡皮巴拉/合成/塔防 四词 + 当关）
      短描述: 卡皮巴拉不许僵尸过路。拖拽两只水豚合体进化，一条道守到大本营。
en-US  title: No Passing: Capybara Merge TD   （29，No Passing 品牌位 + Capybara/Merge/TD）
      短描述: Zombies shall not pass. Merge capybaras, hold the lane, keep the base alive!  （76/80）
```

若要更纯粹的品牌读法，zh 用 9 字版 `水豚当关：合成塔防`（放弃 `卡皮巴拉`，但 `卡皮巴拉` 仍留在长描述首行）。

## 五、必须先过的三关（改名比改文案贵）

1. **Play 内重名**：在 Play Console / 商店搜索 `No Passing`、`水豚当关`，确认没有同品类先占（本次检索未见，但不等于全量）。
2. **商标**：`No Passing` 是通用短语，域名/商标不易独占；`Capybocalypse` 这类自造词反而容易注册。品牌力与可注册性是两条线，得选一条。
3. **改名是独立一轮审核**：标题变更会再进一次审核队列，且审核期间线上仍是旧名。建议**不要在 2026-10-24 那次文案审核未出结果时叠第二次提交**。

## 六、下一步

选定后：`variants/C/` 复制 B 的文案 → 改 title/短描述 → `aso_lint --variant C --baseline B` → Jenkins `TS-Store-Iteration`（`SITE=capybara`、`MODE=dry-run`）→ 人工看 diff → 再决定是否写线上。
