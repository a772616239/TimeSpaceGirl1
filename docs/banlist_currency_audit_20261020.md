## 4. 两个无法判定的：为什么必须归档

`10000015` / `10000016`：

- `user` 文档已被物理删除（`db.user.deleteOne`），`/root/incident_20261018/` 里
  只有 `itemLog/heroLog/fightLog/storeLog` 的空壳文件（`itemLog_10000016.json` 为 **0 字节**）；
- 30 天 `jl_item` BI 窗口里**一行记录都没有**（两个号在窗口内零活动，或活动早于保留期）；
- ⇒ 余额、流水、发放来源**三者全无**。任何"他有/他没有 20 亿"的结论都是猜的。

这就是「删号前必须归档」的由来。现在的做法（2026-10-20 起）：

```bash
python3 scripts/cheatctl.py archive --uid <uid>            # 只读留档
python3 scripts/cheatctl.py purge --uid <uid> --account --confirm <uid> --apply
```

- `archive` 会导出 `user` + **`itemLog`/`heroLog`/`fightLog`/`storeLog` 四个集合** + 榜单快照，
  并把**当时的货币余额（item3/14/16/17/79…）写进 manifest**；
- `purge --account` 把"四个集合是否都导出成功"当硬闸门，**任一失败直接中止删号**。
