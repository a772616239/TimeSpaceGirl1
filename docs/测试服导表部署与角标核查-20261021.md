## 二、🔴 导表链路上一处致命 bug：服务端 txt 空值写 `nil`

第一次（15:10）把导出的表覆盖到本机服后，游戏服**起不来**：

```
[ERROR] STableManager - clazz = [class config.SRechargeCommodityConfig],
        line = [1  3401026] ...
java.lang.NumberFormatException: For input string: "nil"
```

根因链：

1. `DataHelper.GetValByDefault()`（只被 `DataToTxtExporter` 调用）默认值字面量写的是 `"nil"`；
2. 服务端 `StringUtil.parseFiledInt / parseFiledInt2 / parseFiledInt3`（`gamecommon/util/StringUtil.java:20-56`）**只认 `null` / 空串 / 空格**，其余一律 `Integer.parseInt`；
3. `RechargeCommodityConfig` 里 10 个 `mut,int#...` 列共 4547 个空单元格 → 全变 `nil` → 第一行数据就抛异常，整表加载中断。

为什么一直没暴露：导表输出落在**影子目录** `TimeSpaceServer/skzc/home/java/gameserver/conf/server`，
真实服务端仓 `Server_x1tag1.2.2/server_game/conf/server` 从来没被这份导出覆盖过
⇒ 这条链此前从未真正跑通。

修复：`DataHelper.GetValByDefault` 的默认值 `"nil"` → `"null"`（客户端走另一个
`GetClientValByDefault`，空串，不受影响）。**服务端代码不用动，也不用重编 jar。**

验证：`TS-Resource-Build` #14 重新导表后

```
RechargeCommodityConfig.txt   nil=0   null=4547   835 行 × 33 列
md5(新导出) = md5(本机服 conf) = md5(本机服 assets/conf) = 587328393f…9ef67f
```

## 四、角标为什么看不到

角标渲染只有一处，`~Lua/View/ShopView.lua:738-744`（`RechargeShopItemAdapter`）：

```lua
local curBuyCount = itemData.buyTimes
first:SetActive(curBuyCount < 1)          -- ① 买过就永久不显示
firstNum.text = itemInfo.FirstMultiple[1][2]   -- ② 数字来自客户端配置
```

①**服务端数据**：查了本机库 `m5_x1_game_10001.user.playerManager.rechargeInfo.buyGoodsTimes`，
5 个测试账号**都没有 key `"1"`** ⇒ 6 元档 `buyTimes = 0` ⇒ 条件成立，角标应该显示。排除。

②**客户端配置**：`FirstMultiple` 读的是 `~Lua/Config/Data/RechargeCommodityConfig.lua`，
即 **AB 里的内容**。而测试服 `resUrl` = `http://129.226.213.65:81/`（`scripts/build_envs.json`），
与**正式服共用同一个资源站**。只要没往那儿推新 AB，客户端拿到的还是旧配置。

参考值：`id=1`（6 元档）的 `FirstMultiple` 改前 `16#60`、改后 `16#1100`。
若客户端是旧 AB，角标应显示「首充赠 60」；**连 60 都看不到**，说明那个包比 `16#60`
这一版还旧（该值在更早一轮就被写进 xlsx，但同样从没导出到客户端 AB 过）。
