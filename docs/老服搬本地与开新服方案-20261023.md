# 老服（10001 霓虹序曲）搬本地 + 线上开新服 方案

> 更新时间：2026-10-23
> 关联：`server_ops_runbook.md`（生产事实/区服寻址）、`.workbuddy/memory/REF-shard10002.md`（本地服+frp+token 镜像全套踩坑）
> 一句话：**10001 的 Mongo 业务库 + Redis 业务数据搬到本机 Mac 跑游戏服，经线上 frps 暴露；登录服留在线上不动，只改 `server_info.port`。腾出的内存给线上新服 10003。**

---

## 0. 为什么这条链路能成立（先看这 4 条）

| # | 硬依据 | 出处 |
|---|---|---|
| 1 | 客户端登录地址硬编码 `129.226.213.65:8080`，但**游戏服 ip:port 是 `server_info` 动态下发**的 ⇒ 老服 ip 不变、只把 port 改成 frp 端口，**客户端零改包** | runbook §2.1 / §2.4 |
| 2 | token 镜像方案已在 10002 服跑通：线上 Redis `JL_TOKEN:*` keyspace 通知 → 本地 Redis，实测端到端 **291ms** | REF §51 |
| 3 | 线上 Mongo **4.0.10**、本地 **4.0.28**，同大版本，`mongodump/mongorestore` 完全兼容；线上 Redis **7.2.12**、本地 brew 有 `redis@7.2`，可同版本起独立实例 | 实测 |
| 4 | 数据极小：业务库 **58.8MB**、Redis **40.4MB / 6373 keys**、玩家 **218 个** ⇒ 停机窗口可压到 **10~15 分钟** | 实测 |

## 2. 目标架构

```
                        玩家（老服 10001 老号）
                                │  ① 登录 http://129.226.213.65:8080/  （硬编码，不变）
                                ▼
                   ┌────────────────────────────┐
                   │ 线上 129.226.213.65        │
                   │  登录服 Tomcat :8080        │──→ 写 Redis 6379: JL_TOKEN:<uid>
                   │  frps :7700 / :16281        │
                   │  新服 10003 :16082          │──→ 线上 Mongo m5_x1_game_10003
                   │  线上 Mongo 4.0 / Redis 7.2 │
                   └──────────┬─────────────────┘
                              │ ② server_info 下发 129.226.213.65:16281
                              │ ③ frps 反向隧道（16281 → 本地 16083）
                              ▼
        ┌──────────────────────────────────────────────┐
        │ 本机 Mac                                      │
        │  老服 gameserver 10001 :16083（jar 同线上）   │
        │  Mongo 4.0.28 → m5_x1_game_10001（58.8MB）    │
        │  Redis 7.2 @6480（10001:* 业务数据）          │
        │  token 镜像常驻进程（线上 JL_TOKEN → 6480）    │
        └──────────────────────────────────────────────┘
```

**关键：登录服不搬。** 它只做账号校验 + 写 token + 下发区服列表，很轻（346MB），留在线上最省事，也让老服/新服共用同一套登录与账号体系。

## 3. 编号 / 端口 / 资源规划

| 项 | 老服（10001 霓虹序曲） | 新服（10003） |
|---|---|---|
| 进程位置 | **本机 Mac** `~/ts-legacy10001/home/java/gameserver` | 线上 `/home/java/gameserver3` |
| netty 端口 | 本地 **16083**（避开自测服 16081） | 线上 **16082** |
| 公网入口 | `129.226.213.65:16281`（frps 新增） | `129.226.213.65:16082`（直连） |
| Mongo 库 | 本地 `m5_x1_game_10001_legacy`（避免覆盖自测服同名库） | 线上 `m5_x1_game_10003`（自动建） |
| mongodbcore | 本地 `m5_x1_login_legacy`（**必须不存在**，否则 NPE 崩） | 线上 `m5_x1_login_10003`（**必须不存在**） |
| Redis | 本地 **6480**（redis@7.2 独立实例） | 线上 6379（key 前缀 `10003:`） |
| GM 端口 | **7917** | **7918** |
| 其他端口 | chatTcp 20003 / logintcp 17095 / udp 17096 | chatTcp 20002 / logintcp 17093 / udp 17094 |
| 内存 | `-Xmx1280m`（本机充裕） | `-Xmx1024m` 起，观察后调 |
| `server.openCross` | **false**（本地无 worldserver/chatserver） | **false**（线上只剩一个服，跨服无意义） |
| server_info | `_id:1` 只 `$set{port:"16281"}` | 新增 `_id:3`，port `16082`，state `"2"` |

> 为什么老服本地端口用 16083 而不是 16081：本地自测服正占着 16081 + GM 7916。用 16083 可以让**自测服完全不动**，改动面最小；端口对玩家不可见（对外是 16281）。

## 4. 阶段 0：本地环境准备（不影响线上，可提前做）

### 4.1 目录 + `/home/java` 软链（🔴 必做，否则表加载失败主线程崩）

```bash

#   home<TAB>/System/Volumes/Data/home
sudo /System/Library/Filesystems/apfs.fs/Contents/Resources/apfs.util -t
ln -sfn ~/ts-legacy10001/home/java /home/java
ls /home/java           # 必须存在
```

### 4.2 拉线上运行环境（**原样搬，不重编**）

```bash

  gameSrv-1.0.0.jar conf config \
  --exclude="conf/*.bak*" --exclude="config/*.bak*"' > /tmp/gs-10001.tgz
```

## 6. 阶段 2：正式切换（凌晨窗口，目标 15~20 分钟）

**前置**：阶段 1 全绿；提前 24h 发停服公告；确认当时无充值订单在处理中。

### 时间线

| 时刻 | 动作 | 检查点 |
|---|---|---|
| T-30min | 游戏内公告「维护 30 分钟」；关闭新登录 | — |
| T-0 | 线上停游戏服 `pkill -f gameSrv-1.0.0.jar`，等 16081 释放 | `ss -tlnp \| grep 16081` 为空 |
| T+1 | 确认结算落盘：`ls -lt conf/checkout_db*.txt \| head`、`ls -lt conf/mem*.txt` 最后修改时间已停止 | 文件 mtime 不再变 |
| T+2 | **增量 dump**（同阶段 1 命令，覆盖 `/tmp/mig10001`） | dump 成功 |
| T+4 | 打包 + scp 回本地（约 20~30MB 压缩包） | 传输完成 |
| T+6 | restore + Redis 加载（同阶段 1，**先 `mongorestore --drop` 覆盖预演数据**） | user=218、dbsize≈6373 |
| T+8 | 启动本地老服 | 16083 监听、表 406、无 NPE |
| T+11 | **改 `server_info._id:1` 的 port → "16281"** | 只 `$set{port}`，`name/open_time/state` 原样 |
| T+12 | 自测登录一个真实账号 → 进游戏看到角色 | 角色/背包/战力与停服前一致 |
| T+15 | 开服公告 | — |

改区服表（**只改 port，别用 `apply` 脚本，它会刷 open_time**）：

```bash
ssh gs 'mongo --quiet -u a772616239 -p Wang177752 --authenticationDatabase admin x1_cn_test_login \
  --eval "db.server_info.updateOne({_id:1},{\$set:{port:\"16281\"}}); printjson(db.server_info.findOne({_id:1},{ip:1,port:1,server_id:1,name:1,state:1}))"'
```

> 登录服**无缓存、每请求重查**，改完立即生效，不用重启。

### 切换期数据丢失边界

```bash

rsync -av gs:/home/java/gameserver/conf/checkout_db*.txt ~/ts-legacy10001/home/java/gameserver/conf/
rsync -av gs:/home/java/gameserver/conf/mem*.txt       ~/ts-legacy10001/home/java/gameserver/conf/ 2>/dev/null
```

## 9. 回滚（< 3 分钟）

线上数据**全程没动**（dump 只读），所以回滚极干净：

```bash
# 1) 区服表改回
ssh gs 'mongo --quiet -u a772616239 -p Wang177752 --authenticationDatabase admin x1_cn_test_login \
  --eval "db.server_info.updateOne({_id:1},{\$set:{port:\"16081\"}})"'

# 2) 线上重启老服
ssh gs 'cd /home/java/gameserver && sh RESTART-GAMESERVER.sh'

# 3) 本地停服（避免双写）
# 本地停 16083 进程 + frpc
```

⚠️ 回滚会丢掉「切换后老服玩家在本地产生的写入」（切换后到回滚前的进度）。所以回滚只用于**切换后 1~2 小时内发现致命问题**；超过这个窗口，优先修本地而不是回滚。

## 10. 风险与需要拍板的决策点

### 🔴 必须决策

| # | 问题 | 选项 | 建议 |
|---|---|---|---|
| 1 | **线上内存够不够起新服** | A. 现状 3.6GB 硬起（停老服后 available ~1.9GB，新服占 ~1.1GB，只剩 ~800MB，Mongo 缓存会被挤，OOM 风险高）<br>B. 升配到 8GB（腾讯云按需升配，需重启实例） | **B**。这游戏 2C3.6G 本来就榨干，两个 JVM 硬挤必然出问题 |
| 2 | **老服玩家还能不能充值** | A. 关闭充值入口（老服只保留已有资产，不再产生订单）<br>B. 保留充值（需把支付回调路由到本地，改造量大且家宽不稳） | **A**。老服定位是"养老区"，充值走新服 |
| 3 | **老服保留多久** | A. 长期（家宽+Mac 常开）<br>B. 过渡期 1~3 个月，之后合服/关服 | 建议先按 **B** 设计，成本可控 |
| 4 | **新服编号** | A. 10003（与本地 10002 不冲突）<br>B. 复用 10001 清档（玩家看到同名区但数据重置，体验差） | **A** |
| 5 | **老服版本** | A. 冻结在搬迁时的 jar（推荐）<br>B. 后续继续跟线上热补丁 | **A**。老服不跟版本，避免每次发版都要同步两份 jar |

### ⚠️ 已知限制（10002 已验证过的坑，老服同样适用）

1. **家宽无兜底**：断电/动态 IP/Clash 规则丢失都会掉线；Mac 必须常开且登录桌面会话（launchd LaunchAgent 只在 GUI 登录后加载）。
2. **跨服功能不可用**：世界聊天、跨服排行、跨服战（本地无 worldserver/chatserver/global）。`server.openCross=false` 关掉。
3. **玩家 RTT 增加**：欧洲 ≈284ms、美洲 ≈306ms（10002 实测）。老服是养老区可接受，但要提前告知玩家。
4. **GM 后台要改**：老服 GM 在本地 7917，线上 GM 后台需 SSH 隧道才能操作老服。
5. **`/home` 合成路径**：Mac 重启后 `/home` 可能消失 → 游戏服起不来（日志只有 START 横幅、极易误判在跑）。用 `fix-home-synthetic.sh` 幂等修复。
6. **代理污染**：frpc / token-sync 启动必须 `env -u` 剥代理变量；Clash 订阅更新会冲掉 DIRECT 规则。
7. **本地自测服冲突**：老服占 16083 + GM 7917 + Redis 6480 + 库 `_legacy`，与自测服（16081/7916/6379/`m5_x1_game_10001`）完全隔离，互不影响。

## 12. 待补的自动化脚本（落地时写）

| 脚本 | 作用 |
|---|---|
| `~/ts-legacy10001/all.sh {start\|stop\|restart\|status}` | 四件套统一入口（Redis/游戏服/frpc/token-sync） |
| `~/ts-legacy10001/detach.sh` | 脱离会话启动（`Popen(start_new_session=True)`） |
| `~/ts-legacy10001/token-sync.sh` | 线上 `JL_TOKEN:*` keyspace 通知 → 6480（v2 推送式 + 120s 全量兜底） |
| `~/ts-legacy10001/switch-port.sh {local\|online}` | 一键改 `server_info._id:1` 的 port（切 16281 / 回 16081） |
| `~/ts-legacy10001/fix-home-synthetic.sh` | `/home` 合成路径幂等修复 |
| `~/Library/LaunchAgents/com.tsg.legacy10001.{redis,shard,frpc,tokensync}.plist` | launchd 托管（RunAtLoad + KeepAlive + 置空代理） |

> token-sync 的关键配置：线上 Redis 需 `notify-keyspace-events = K$g`（`K` keyspace 通道、`$` string 的 SET、`g` 的 DEL/EXPIRE），**缺 `$` 收不到 SET**。这是运行时配置，不改 redis.conf、不重启；但 Redis 重启会回落，脚本每 120s 幂等重设。
